# Anschlussvollständigkeit

Lauf37035 wurde nach belegtem Quellenwiderspruch regulär und gemäß aktueller menschlicher Autonomieanweisung abgebrochen: Eine vollständige Gruppe aus vier aktiven ECUs enthielt nur einen Anschluss. Der Server bestätigte CANCELED, der Client Exit1; kanonische Tabellen und Jobs blieben leer. Keine Modellabnahme und kein Release-FAIL daraus erfunden.

Die private Ausgabestruktur und ihr Decoder verlangen für einen vollständigen Anschlussplan mindestens einen Anschluss je ausgewähltem elektronischen Teilnehmer. Fehlende einzelne Funktionszuordnungen rechtfertigen keine leere Anschlussliste. Echte offene Auslegungsentscheidungen können ausdrücklich unvollständig mit gezieltem unresolved-Befund gemeldet werden; sie werden nicht als vollständige Planung übernommen. Die normale Validierungsrückmeldung erhält den tatsächlichen Befund. Keine Hardware/Technologie wird zur Erfüllung des Gates erfunden.

Nachweise: 3 unabhängige RED-Gegenproben; danach 37/37 gezielte Tests und ein vollständiger grüner Lauf mit340 Tests, Exit0. Offene Hardwarebefunde bleiben gespeichert. Dieser Lauf endet vor Parameterplanung und ist ausdrücklich keine Original- oder Simulationsabnahme. Vollständige Rohstreams, tatsächliche Modellidentität und unveränderte131072/8192-Grenzen wurden unabhängig geprüft.

Öffentliche Schemas, Quellen, Mengen, Modell-/Timeoutgrenzen und Releasegates bleiben unverändert. Produktion enthält diese Korrektur noch nicht.
