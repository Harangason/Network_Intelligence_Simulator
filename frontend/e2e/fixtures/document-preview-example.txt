Musterprojekt – Fahrzeugnetzwerk

## 1. Systemumfang

- **100 Sensoren**
- **100 Aktuatoren**
- **50 Funktions-ECUs**
- **1 zentrales Gateway**
- Kommunikationssysteme:
  - **25 LIN**
  - **10 CAN-FD**
  - **5 Automotive Ethernet**
- **je Funktion-ECU min 5 und max 20 Signale anlegen, die Anzahl richtet sich an die Notwendigkeit zur Darstellung der Funktionsrelevantendaten   

---

## 2. Sensoren

Die 100 Sensoren erfassen typische fahrzeugrelevante Größen, zum Beispiel:

- Temperatur
- Druck
- Drehzahl
- Raddrehzahl
- Beschleunigung
- Lenkwinkel
- Spannung
- Strom
- Füllstand
- Position
- Abstand
- Zustände
- weitere physikalische Messgrößen

Jeder Sensor erhält mindestens:

- eindeutige ID
- Name
- Beschreibung
- Messgröße
- Einheit
- Minimum
- Maximum
- Auflösung
- Zykluszeit
- Producer-Zuordnung
- angeschlossenes Interface
- verwendete Kommunikationstechnologie

---

## 3. Beispiel Temperatursensor

- Bereich: **−20 °C bis +120 °C**
- Auflösung: **0,1 °C**
- Signal: `Temperature`
- Verwendung durch eine Thermal-/Klima-ECU

Die ECU verarbeitet daraus beispielsweise:

- `TemperatureCurrent`
- `TemperatureTarget`
- `TemperatureStatus`
- `OverTemperatureWarning`
- `ThermalControlRequest`

---

## 4. Beispiel Drehzahlsensor

- Bereich: **0 bis 5000 U/min**
- Auflösung: **50 U/min**
- Signal: `MotorRPM`

Mögliche Werte:

- 0
- 50
- 100
- 150
- …
- 4900
- 4950
- 5000 U/min

Beispielregeln:

- ab 4800 U/min → Warning
- über 5000 U/min → Grenzwertverletzung

---

## 5. Beispiel Stromsensor

- Bereich: **0 bis 20 A**
- Auflösung beispielsweise: **0,1 A**

Verwendung:

- Motorstromüberwachung
- Lastbewertung
- Plausibilitätsprüfung
- Fehlererkennung

Beispiel:

```text
MotorCurrent > 5 A
AND
MotorRPM = 0

→ MOTOR_BLOCKED_POSSIBLE
```

## 10. Kommunikationstechnologien

### LIN

Verwendung für:

- sensornahe Teilnehmer
- einfache Aktuatoren
- Komfortfunktionen
- kostengünstige Kommunikation
- weniger zeitkritische Daten

### CAN-FD

Verwendung für:

- klassische Fahrzeugfunktionen
- Antrieb
- Fahrwerk
- Bremse
- Body-Funktionen
- zeitkritische Steuergeräte

### Automotive Ethernet

Verwendung für:

- zentrale Steuergeräte
- Fahrerassistenz
- datenintensive Kommunikation
- Diagnose
- Infotainment
- Backbone-Kommunikation

---

## 11. Zentrales Gateway

Es existiert **genau ein zentrales Gateway**.

Aufgaben:

- Verbindung der LIN-, CAN-FD- und Ethernet-Segmente
- Routing
- Message Forwarding
- Signalweiterleitung
- Protokollübergänge
- Gateway Queueing
- Gateway Timing
- Gateway Load Monitoring

Das Gateway muss technisch nachvollziehbar zeigen:

- welche Messages es passieren,
- welche Signale weitergeleitet werden,
- welche Bussegmente beteiligt sind,
- welche Verzögerung entsteht,
- welche Last erzeugt wird.

---

## 12. Routing-Tabelle

Für jede relevante Kommunikation wird definiert:

- Producer
- Consumer
- Signal
- Message
- Source Interface
- Source Network
- Gateway
- Destination Network
- Destination Interface
- Routingpfad
- Zykluszeit
- Priorität
- Timing-Anforderung

Beispiel:

```text
ECU_A
→ CAN_FD_1
→ Central Gateway
→ Ethernet Backbone
→ ECU_B
```

## 18. KI-Unterstützung

Die KI unterstützt bei:

- ECU-Definition
- Signaldefinition
- Interface-Erstellung
- Message-Erstellung
- Routing
- Parameter-Vorschlägen
- Fehleranalyse
- Capacity-Analyse
- Simulation
- Trace-Auswertung

Die KI kann größere Workloads verarbeiten.

Beispiel:

```text
Erzeuge für 50 ECUs
alle logisch notwendigen
Eingangs- und Ausgangssignale.
```

Der Agent zerlegt den Auftrag in Work Packages und prüft anschließend:

- geforderte Menge
- erzeugte Menge
- gültige Menge
- fehlende Objekte
- Duplikate
- Fehler

- Funktionslogik
- Messages
- Routing
- Netzwerkparameter

## 20. Signalverhalten

Mögliche Signalprofile:

- Constant
- Ramp
- Step
- Sine
- Pulse
- State dependent
- Formula based
- Lookup Table
- External Series

Die Werte müssen innerhalb der Signaldefinitionen bleiben.

---

## 21. Golden Trace

Die Simulation kann einen fehlerfreien:

```text
GOLDEN TRACE
```

erzeugen.

Eigenschaften:

- plausible Signalwerte
- korrekte Signalauflösung
- korrekte Zykluszeiten
- konsistente Signalabhängigkeiten
- korrektes Routing
- keine künstlich injizierten Fehler

Dieser Trace dient als Referenz.

10 CAN-FD
