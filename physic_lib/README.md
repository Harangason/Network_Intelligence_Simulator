# physic_lib

Runtime and generated artifacts are stored here so the project root stays limited to source, configuration, and documentation.

## Structure

- `Config/simulation_config.db`
  Package modes, signal value strategies, CAN/Ethernet output formats, and Physical-AI skill names.
- `Automotiv/Requests/<project>/<maneuver>/<mode>/`
  MBSE request JSON files generated by `nemotron.py`.
- `Automotiv/SmokeTests/`
  BLF/DBC and package artifacts from smoke/regression runs.
- `Automotiv/TestData/RoutingTables/`
  Routing CSV fixtures and examples.
- `PhysicalAI/Workflows/<workflow>/`
  Physical-AI/NuRec workflow request files.
- `PhysicalAI/Checks/<workflow>/`
  Physical-AI/NuRec readiness and installation check outputs.
- `Samples/`
  Legacy or sample generated folders that do not contain enough metadata for stricter classification.

## Rule

Generated files should not be left in the repository root. `nemotron.py` writes `generated_*.json` directly into the matching request folder.

Runtime configuration dictionaries and lists are loaded from SQLite databases in this library. The code keeps built-in defaults only as seed/fallback data so the tool can bootstrap a fresh workspace.

Emulated trace output is stored outside this library under `traces/Automotive/<timestamp>_<scenario>/`. That folder contains the generated `traces/`, `datenbasen/`, `generation_manifest.json`, and `simulation_interface.json` artifacts.
