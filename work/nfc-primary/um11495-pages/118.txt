13.5  Firmware signature and version control
In the PN7160 sFWu procedure, a mechanism ensures that only a firmware signed and delivered by NXP will
be accepted. In case of signature mismatch, an error DL_SIGNATURE_ERROR is responded to the first secure
write command of the sequence.
Furthermore, the firmware update is only possible if the new firmware major version number is
bigger or equal to the current one. If not, the first secure write command is responded with error code
DL_FIRMWARE_VERSION_ERROR.
13.6  Degraded mode
During sFWu procedure, after the first secure write command passed, if any of the following events occurs the
sFWu procedure will be incomplete:
• Reset (hardware or software)
• Hash chain broken during the download
• Protocol error in framing
• EEPROM critical failure
If previous sFWu procedure did not complete successfully, PN7160 will enter in degraded mode (except if
DWL_REQ pin is set to 1, in that case PN7160 will enter in download mode). In this mode, all the commands
(sFWu or NCI) will be responded with error code DL_SFWU_DEGRADED indicating a new sFWu procedure is
required to recover from this state.
