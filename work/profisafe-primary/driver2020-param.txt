4.1.2 psd_FParBuild(...) 
Parameterization of a PSD instance. 
The F-parameters are read from the stack interface and via psd_GetFParPtr(…)  in the 
function and then a plausibility check is performed. 
The function parameters (source, destination address, SIL) passed in a structure (Fw_FPar), 
which must be determined independent of the F-parameters by the F-application, are 
compared with the read F-parameters by the PSD. 
The structuring of Fw_FPar depends on the "COMPARE_F_SOURCE_ADD" setting in 
p_c_config.h. The structure additionally contains the F_Source_Address with the Define.  
The function can be called in the (instance-specific) PSD states PSD_INIT and PSD_PARAM. 
In the case of invalid F-parameters, the PSD state PSD_INIT is assumed. In the case of valid F-
parameters, the PSD state PSD_PARAM is assumed. 
In the state PSD_DATAEX parameterization with F-parameters is rejected.

4.1.6 psd_RecvFOutTele(...): 
 
 Note 
Call this function cyclically in your F-application. 
 
Reception of F-output frame from the F-host in the PSD for the specified instance. 
The PSD calculates whether or not there is a timeout with the passed 1 -ms time values of the 
two channels. 
The function takes the cyclic F-output frame in the PSD OutData buffer. 
In the 2-channel generation variant, the ClockValue time value is generated by the timer on 
CPU1 and the ClockValueC2 time value is generated by the timer on CPU2.  
The two time values (ClockValue, ClockValueC2) must also be generated in the 1 -channel 
generation variant with two independent hardware timers. 
The tolerable difference between the two values must be determined and verified by the F -
application. 
The PSD uses the psd_GetOutputTelegram(...) function to read the F-output frame and 
checks that the frame conforms to the rules of the PROFIsafe profile /1/. 
The acquisition of the output frame is bracketed with the disable_int(...) and enable_int(...) 
functions in order to ensure consistency.

5.3 Instance addressing 
#undef INST_ACCESS_POINTER 
With instances >1, addressing of the PSD instance data is made through array index accesses. 
Depending on the compiler used this can mean a faster access method. 
With only one instance, the addressing always made via the array index accesses, wherein 
the array index "0" is used as a constant. 
#define INST_ACCESS_POINTER 
With instances >1, addressing of the PSD instance data is made through pointer accesses. 
Depending on the compiler used this can mean a faster access method.  
5.4 Checking of the source address 
#undef COMPARE_F_SOURCE_ADD 
The F-source address is not transferred from the F-application to the PSD with the 
psd_FParBuild(...) function. 
#define COMPARE_F_SOURCE_ADD 
The F-source address is transferred from the F-application to the PSD with the 
psd_FParBuild(...) function. The PSD compares it with the F-source address of the F-
parameters. 
5.5 Support of the V1 communication mode 
#undef V1_MODE 
The V1 communication mode was defined in the early days of PROFIsafe communication. In 
the meantime this has been replaced by the V2 communication mode. The V1 mode is not 
accepted when checking the F-parameters. The cyclic data exchange is thus not possible in 
V1 mode. 
#define V1_MODE 
The V1 mode is accepted when checking the F-parameters. \nPDF_PAGE76\nConfiguration of the PSD

5.7 Integration of fault insertion tests in the PSD OP code 
#undef FAULT_INSERTION_TEST 
Fault-insertion tests are not possible. The error code is deactivated by the compiler switch.  
#define FAULT_INSERTION_TEST 
The error code is activated by the compiler switch. Fault insertion tests can be activated with 
the psd_SetFID(...) interface function. 
 
 
 WARNING 
Requirement: PSD_RQ_0_13 
The fault insertion tests specified in the section Fault insertion test (Page 84) must be 
performed in accordance with their description. In a release generation, the fault insertion 
testing must be disabled by disabling the "FAULT_INSERTION_TEST" define in p_c_config.h 
when no measures are installed in the F-application to prevent accidental activation of a 
fault insertion test. The measures (for example, password protection when activating the 
fault insertion tests, time limitation in the activation process of a fault insertion test, etc.) 
are to be agreed upon together with the competent licensing authority in accordance with 
the desired safety level. 
 
5.8 Consecutive No. for fault-insertion test activation 
#define CONS_NR_FOR_FIT_ACTIVATION value 
A fault insertion test, which has been activated by the psd_SetFID(...) function, is not 
performed until the PROFIsafe frame has reached the defined consecutive number.
