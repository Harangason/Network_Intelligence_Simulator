L284@P14: 3 Overview
L285@P14: This section introduces Device Information Model definition and usage.
L286@P14: Device Information Model definitions represent collections of device data points. A device
L287@P14: implementation based on the information models can use the model definitions to standardize
L288@P14: the interface to device data points. This includes logically grouping the information to
L289@P14: correspond to the data point grouping requirements of a device.
L290@P14: 3.1 Device Information Model Structure
L291@P14: Device Information Models are defined using the following definition elements:
L292@P14: • model
L293@P14: • point
L294@P14: • point grouping
L295@P14: • symbol
L296@P14: • comment
L297@P14: The point definition element represents the Device Information Model data, and the other
L298@P14: definition elements govern data structuring and usage. The following figure shows the primary
L299@P14: definition elements’ structural relationship.
L300@P14-15: Figure 2: Device Information Model ElementsSunSpec Device Information Model Specification 16 sunspec.org
L301@P15: 3.1.1 Model
L302@P15: The model definition element includes all the definition elements. It is used as the container for
L303@P15: the logically related set of device data points, for a particular model.
L304@P15: 3.1.2 Point
L305@P15: The point definition element defines a Device Information Model data point. Point elements hold
L306@P15: data values that correspond to a device property. There are typically multiple point definitions in
L307@P15: the model definition.
L308@P15: 3.1.3 Point Group
L309@P15: The point group definition element provides a way to logically group a set of points. There are
L310@P15: three reasons to group points:
L311@P15: • The top-level model organization construct is always a point group. The first element in a
L312@P15: model definition is the top-level point group and includes all the point and point group
L313@P15: definitions in the model.
L314@P15: • A repeating set of points can be grouped, creating multiple instances of the point group
L315@P15: that can be accessed as an array of point groups.
L316@P15: • A set of points with synchronous operational requirements can be grouped, indicating
L317@P15: that the points in the group must be read and written atomically.
L318@P15: 3.1.4 Symbol
L319@P15: The symbol definition element assigns identifiers to values associated with a point definition
L320@P15: element. Symbols define the set of valid values for the point and provide identifiers that can be
L321@P15: used to represent the value.
L322@P15: 3.1.5 Comment
L323@P15: The comment definition element associates a comment string with any of the other definition
L324@P15: elements. It can be used to document the element definition.
L325@P15: 3.2 Device Information Model Definition and Instance Relationship
L326@P15: It is important to understand the relationship between a Device Information Model definition and
L327@P15: a Device Information Model instance.
L328@P15: A Device Information Model definition specifies the data points that make up the Device
L329@P15: Information Model and the usage information associated with each data point. There is one
L330@P15-16: definition for each Device Information Model.SunSpec Device Information Model Specification 17 sunspec.org
L331@P16: Figure 3: Device Information Model Definition-Instance Map
L332@P16: A Device Information Model instance is created from a Device Information Model definition. The
L333@P16: instance includes data point values specified for each of the defined data points. There can be
L334@P16: any number of Device Information Model instances.
L335@P16: The canonical form of Device Information Model definitions is specified in a JSON encoding. For
L336@P16: convenience, alternative Device Information Model definition representations can be used
L337@P16: provided they preserve all the Device Information Model definition content. In addition to the
L338@P16: canonical JSON encoding, this specification standardizes a CSV encoding for Device
L339@P16: Information Model definitions to support a spreadsheet presentation of the definitions.
L340@P16: 3.3 Device Information Model Usage
L341@P16: Devices use the Device Information Model definitions that represent the data points supported
L342@P16: by the device. Further, a device implementation includes the collection of Device Information
L343@P16-17: Models that correspond to the full set of device data points.SunSpec Device Information Model Specification 18 sunspec.org
L344@P17: Figure 4: Device Information Model Instance
L345@P17: Information can be exchanged with a device by requesting some or all the device data points,
L346@P17: using a communication interface that implements the standardized Device Information Models.
L347@P17: Device Information Model definitions are interface-independent. This specification standardizes
L348@P17-18: Device Information Model usage for both Modbus, and JSON data representations.SunSpec Device Information Model Specification 19 sunspec.org
L349@P18: 3.3.1 Modbus
L350@P18: Device Information Models can be mapped into a Modbus address space. A collection of Device
L351@P18: Information Models can be used to create a Modbus map that corresponds to the data points
L352@P18: supported by the device.
L353@P18: 3.3.2 JSON
L354@P18: Device Information Model contents can be represented as JSON objects. Devices can access
L355@P18: data points supported by the device through an interface that supports JSON objects, such as a
L356@P18-19: RESTful web service.SunSpec Device Information Model Specification 20 sunspec.org

L393@P20: 4.1.2 Point Group Element
L394@P20: The point group element includes point elements or other point group elements.
L395@P20: The point group type MUST either be group or sync.
L396@P20: The group point group type is used to create a set of points and point groups. If the count for the
L397@P20: point group is greater than one, the point group repeats the number of times specified by count.
L398@P20: The count attribute can be defined as a constant in the point group definition or be specified as
L399@P20: the value of another point in the model definition. If the point group count is specified in another
L400@P20: point, that point MUST be defined in the top-level point group of the model before the point
L401@P20: group definition.
L402@P20: The sync point group type is used to designate points and point groups that MUST be read and
L403@P20: written atomically. Implementations MUST indicate an error if all the members of a sync group
L404@P20: are not able to be read or written atomically.
L405@P20: The order of the point group members is significant and MUST be maintained.
L406@P20: All points in a point group MUST be defined before any point groups are defined.
L407@P20: See Table 2: Element Attributes for the valid mandatory and optional element attributes for a
L408@P20: point group element definition.
L409@P20: 4.1.3 Point Element
L410@P20: The point element defines a data point element.
L411@P20: The size of the data element MUST be specified for points that have a type of string.
L412@P20: If the count for the point is greater than one, the point repeats the number of times specified by
L413@P20: the count. The count attribute can be defined as a constant in the point definition or be specified
L414@P20: as a value of another point in the model definition. If the point count is specified in another point,
L415@P20: that point MUST be defined in the top-level point group of the model before the point definition.
L416@P20: See Table 2: Element Attributes for the valid mandatory and optional element attributes for a
L417@P20: point element definition.
L418@P20: 4.1.4 Symbol Element
L419@P20: The symbol element associates an ID with a constant point value in a point definition.
L420@P20: The symbol element MUST be associated with a point definition. A point definition MAY have
L421@P20: multiple symbols associated with it. Each symbol ID MUST be unique for that point definition.
L422@P20: The symbol definitions for a point definition serve as a set of possible enumerated values that
L423@P20: are valid for the point. If a point has associated symbols defined, all values not in the set of
L424@P20: symbol definitions MUST be considered invalid by an implementation.
L425@P20: See Table 2: Element Attributes for the valid mandatory and optional element attributes for a
L426@P20: symbol element definition.
L427@P20: 4.1.5 Comment Element
L428@P20: The comment element is a single string and is associated with any valid definition element other
